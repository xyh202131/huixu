# 会序执行计划 · 五个问题与解决方案

问题梳理以本地 `main` 提交 `7e44da3` 为基准。三个阶段的本机交付与验收记录见 [任务清单](../task.md)。负责人在工作台维护计划和报名，参与者使用公开报名页或自己的确认链接。

## 1. 只有一个主题和少量人员信息，能否直接生成活动方案？

**可以做成只输入主题就生成方案。** 当前一句话入口使用活动名称、类型和人数创建草稿，议程按活动类型套用预设。资料整理已有可编辑的方案入口，可作为新流程的落点。[当前创建入口](../web/src/App.jsx#L62) · [当前方案编辑](../web/src/ImportReview.jsx#L180)

- **新增入口。** 在「新建活动」提供「从主题生成方案」。主题是唯一必填项。受众、已知人数、参与人员、日期、地点和预算均可补充。只输入「校园 AI 工具分享会」也能先生成草案。
- **生成整份可编辑方案。** 输出活动目标、受众、建议流程、相对时长、岗位分工、物料、预算项目和筹备任务。负责人可以逐项增删、改写和保存。已知信息直接带入，建议时长和预算估算明确标为建议，日期、场地、嘉宾或金额缺失时标为待确认。需要场地和时间才能校验的条目等信息补齐后再校验。
- **引用过往活动。** 提供「参考过往活动」，由负责人选用同类模板或团队已审核的复盘。优先复用议程结构、任务顺序、岗位和物料，显示参考活动及具体复用内容。人员、联系方式、历史价格和场地限制按本场重新确认。没有可引用历史时，照常生成通用草案。[长期记忆设计](agent-memory.md)
- **验收。** 分别用「仅主题」「主题加两名已知参与人员」「主题加已审核案例」生成并重新打开草稿。检查可编辑、保存后可恢复、历史来源可追查、未知事实有明确标记。

## 2. 突发情况能否让 AI 直接给整个活动的解决方案？

**可以让 Agent 一次提交整场调整方案，由负责人确认发布。** 当前工具一次校验一个环节的换厅或改时，已有容量、设备、人员和发布影响校验，可复用这些规则来检查多环节组合。[当前 Agent 排程工具](../web/server/agent.js#L25)

- **统一上报。** 在「现场执行」提供「生成整场调整方案」。负责人可以上报主会场停用、嘉宾迟到和环节超时。Agent 读取当前发布版、现场实绩、可用会场和设备、人员时段、分场报名及岗位。已经发生的实绩保留，正在进行环节的剩余处置交由负责人决定。
- **生成并联合校验备选。** 一套方案包含多个环节的换厅、改时、对调、分批或取消建议，并列出照常执行的环节。整套校验场地容量、场地和人员撞期、布撤场与转场、设备、嘉宾可用时间。无可行解时给出具体卡点和可选取舍，例如「现有会场容量不足，可以分批或寻找备用会场」。
- **一次核对和发布。** 同一张变更单对照旧安排与新安排，列出受影响的报名、签到点、岗位、台本、指引物料、现场大屏和通知对象。确认前按最新数据复查。整套安排发布为同一个版本，按已确认范围生成通知记录。实际移动设备、换指引牌等任务显示交接人和完成状态。
- **验收。** 模拟 A 厅停用并影响两个工作坊。B 厅容量 60，无法承接 72 位已确认观众的工作坊。C 厅需要布置时间，调整两个工作坊后复查占用。另模拟确认期间 C 厅被占用，系统应拦截旧方案并保留当时的现场实绩。

## 3. 发邮件目前为什么只能演练，怎么接通？

**现在只能预览并记录演练。** 「材料与沟通」已有按场次和报名状态预览通知的入口。需要接入团队认可的邮件服务，才能真实发信并回查结果。[当前材料与沟通](../web/src/Attendees.jsx#L170)

- **接通发信。** 配置发件地址和回复地址，先向测试邮箱验收。通过后在「材料与沟通」开放实际发送，沿用「选人 → 核对收件人、正文和活动版本 → 负责人确认」流程。
- **覆盖活动邮件。** 优先打通报名邀请、审核结果、出席确认邀请、活动变更和提醒。缺少邮箱的参与者显示为待补信息。活动变更邮件引用本次确认发布的版本和受影响人员。
- **按人显示结果。** 区分待发送、已提交给邮件服务、发送失败和服务商可确认的送达状态。结果未知时先核查，只重试确认失败的邮件，重复点击同一发送动作只生成一份发送记录。
- **验收。** 负责人用测试活动向两个受控邮箱发送不同内容，其中一条模拟确定失败。检查实际收件、收件范围、发送状态和仅重试失败项。服务商和发件配置在实施时确定。

## 4. 报名变化要重新导表吗？能否通过邮件确认后自动关联？

**可以让报名在网页上维护，并由邮件里的专属链接更新同一条记录。** 现在登录后已经可以确认报名、加入候补、转候补，公开表单也能提交演练报名。姓名、邮箱和分场还不能完整在线维护，报名保存在本机浏览器，真实参与者跨设备操作需要服务端共享数据。[现有报名管理](../web/src/Attendees.jsx#L34) · [现有活动存储](../web/src/App.jsx#L145)

- **建立共享报名名单。** 将活动发布版、分场容量、报名和凭证所依赖的数据接到同一个服务端。负责人可以新增、搜索和编辑姓名、邮箱、分场及备注。参与者只能查看和操作自己的记录，负责人按活动权限管理名单。
- **Excel 支持首次导入和批量更新。** 上传后先预览新增、匹配更新、重复和待处理项。优先按已有报名编号匹配，其次使用本场内唯一的邮箱，同名且无法唯一匹配时交给负责人选择。保留原报名编号，表格缺行不触发删除，冲突和无法匹配的记录留待核对。已有本地真实数据在迁移前给负责人核对范围。
- **邮件确认回到原记录。** 邮件链接仅打开该参与者的确认页，参与者点击提交后才改变状态。分开记录「审核状态」和「出席状态」，例如「已审核通过 · 尚未确认出席」。允许确认出席、报告无法参加或申请换分场。链接限定活动和报名，可过期或撤销，重复提交不重复占位。释放名额和候补补位按活动规则处理，换分场在服务端复查容量。直接回复邮件的自动识别可在链接回流验收后再设计。
- **验收。** 负责人在电脑上把某位观众改到另一场，参与者用独立手机浏览器打开邮件确认，负责人刷新后能看到确认结果。重复提交保持同一条记录。两人同时争最后一个分场名额时，名额上限仍生效。旧凭证和已有签到可追溯。

## 5. 如何体现 PPT 和海报设计辅助？

**先交付可预览、可编辑、可复制的提示词。** 在「材料与沟通」增加「设计材料」，与现有从计划版本生成议程、主持稿和台本的入口并列。[当前材料类型](../web/src/model.js#L7)

- **PPT 提示词。** 支持按开场介绍、活动介绍或分享课件生成。输入页数和受众后，输出逐页标题、要点、版式或图表建议，可选讲稿提示。讲者、日程和活动数据来自所选计划版本。
- **海报提示词。** 输出可直接用的主副标题、正文、时间地点、报名入口、适用尺寸、图像方向和构图。支持用户选择是否给设计工具指定色调或风格。没有正式报名链接时保留二维码占位，日期、场地等待确认信息保留占位并提示核对。
- **验收。** 同一活动生成 PPT 与海报提示词，核对其名称、时间地点和报名入口一致。活动改期后重新生成，检查采用更新后的计划版本。复制的文本可直接交给常用设计工具。

## 分阶段执行与交付

| 阶段 | 执行项 | 依赖和交付条件 |
| --- | --- | --- |
| 一 · 方案起草和设计材料 | 1. 主题生成可编辑方案。2. 选择同类模板或已审核案例，并显示参考依据。3. 从同一方案生成 PPT 和海报提示词。 | 复用现有方案编辑和材料入口。先支持负责人明确选用案例，随团队记忆权限和审核能力接入跨活动检索。主题起草与设计材料可在本地用虚构活动验收。对应 [T03、T07、T15](../task.md#任务清单)。 |
| 二 · 在线报名、邮件与回流 | 1. 建立活动和报名的服务端记录及访问权限。2. 接入网页编辑与 Excel 批量更新预览。3. 接通真实邮件、发送结果和确认链接。 | 网页编辑与名单不依赖发信，邮件确认依赖服务端报名与可公开访问的确认页。发信需已配置发件地址。用组织者与参与者分开的浏览器或设备验收。对应 [T01、T06、T07](../task.md#任务清单)。 |
| 三 · 整场救场 | 1. 扩展整场影响分析和组合校验。2. 组织多环节变更单，一次确认发布。3. 同步各端并按影响范围通知。 | 组合校验可提前用本机样例开发。正式发布和通知联测读取服务端的最新报名与资源。验证正常发布、确认数据过期、无解和邮件部分失败。对应 [T08、T09](../task.md#任务清单)。 |

**贯穿验收**采用一场虚构的 150 人论坛。负责人只提供主题生成计划，补齐场地和议程后生成两类设计提示词。参与者从自己的手机完成报名和邮件确认。现场模拟主厅停用及两个环节受影响，负责人选择替代方案并发布，核对参与者看到的议程、现场签到点、岗位台本和已发通知是否对应同一版本。
