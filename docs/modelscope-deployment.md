# 会序在魔搭创空间运行

使用 Docker 类型的创空间。容器启动 Node.js 24 服务，监听 `0.0.0.0:7860`，同时提供工作台页面和活动 API。镜像内包含 Office、PDF、OCR 和压缩包解析依赖。首个 Docker 空间需要账号已绑定阿里云并完成实名认证。[魔搭 Docker 创空间文档](https://modelscope.cn/docs/studios/docker)

## 运行时配置

| 配置项 | 类型 | 用途 |
| --- | --- | --- |
| `HUIXU_PUBLIC_ORIGIN` | 明文 | 应用的完整 HTTPS 源，例如 `https://owner-huixu.ms.show`。用于登录安全校验和生成嘉宾、报名及交接链接。 |
| `HUIXU_OWNER_EMAIL` | 明文 | 创空间账号库为空时，用此邮箱预设首位负责人。已有账号的创空间沿用原账号。 |
| `HUIXU_OWNER_PASSWORD` | 密文 | 首位负责人的登录密码，长度 12–128 字符。与邮箱一起配置，账号建立后可从平台运行时配置移除此变量。 |
| `HUIXU_SIGNUP_CODE` | 密文，可选 | 至少 32 字符的独立随机邀请码。首位负责人创建后开放其他账号注册，留空时保留已有账号登录。 |
| `HUIXU_MODEL_ORIGINS` | 明文，可选 | 运维批准的自定义 HTTPS 模型源，用逗号分隔。云端内置模型服务及魔搭推理源可直接在界面填 Key。 |
| `HUIXU_LLM_PROTOCOL`、`HUIXU_LLM_BASE_URL`、`HUIXU_LLM_MODEL`、`HUIXU_LLM_API_KEY` | 可选，API Key 用密文 | MiniMax 官方接口配合 MiniMax 模型和密钥时，提供访客和登录账号都能用的平台 MiniMax。其他服务端后备模型供首位负责人使用。 |
| `HUIXU_LLM_KEY_HEADER` | 明文，可选 | 用于 Anthropic 兼容接口，可填 `bearer` 或 `x-api-key`。原生 Anthropic 默认 `x-api-key`，MiniMax 默认 `bearer`。 |
| `HUIXU_RESEND_API_KEY`、`HUIXU_MAIL_FROM` | 可选，API Key 用密文 | 首位负责人的正式邮件投递渠道，需要参与者可访问的空间地址及已验证发件域。 |

私有空间从已登录的魔搭创空间页面打开。嵌入工作台的负责人会话依赖浏览器支持 HTTPS 分区 Cookie。私有访问权限也适用于应用域名、报名和嘉宾链接。

账号库为空的创空间，先在部署设置中填好负责人邮箱和密码。应用首次加载账号服务时会用这两个值建立账号。之后从工作台头像直接登录。升级仍在等待首次建号的旧空间时，用这两个变量替换 `HUIXU_SETUP_CODE`。已建号空间沿用现有账户和数据目录。

应用将账号、工作区、Agent 对话、模型设置、活动索引、草稿、报名、已发布议程和嘉宾课件写入 `/mnt/workspace/huixu`。账号与报名分别使用共享的账号库和按活动负责人校验权限的报名库。每位账号的工作区在 `accounts/<账号 ID 哈希>/workspace.sqlite`，邀请注册的账号使用各自目录中的资料与模型数据库。首位负责人继续读取此前的资料索引和模型库。部署时保留整个数据目录，迁移或改名时另行备份。模型作为外部服务调用，部署令牌只用于创空间管理。

模型 Key 在各账号的模型库中加密，派生材料保存在同一部署的账号库。备份和恢复时一起保留账号库和模型库。升级到新版后，访问模型设置时会加密该账号以前保存在服务器的明文 Key，并迁移仍保存在浏览器且已标注该账号的旧配置。服务端现有设置优先。

平台 MiniMax 沿用当前服务端变量，例如 `anthropic`、`https://api.minimaxi.com/anthropic` 和 `MiniMax-M3.1-Flash`。浏览器仅获取可选模型的名称。每个运行实例的平台调用共享每分钟 60 次上游请求和 4 个上游并发的额度，包含对话内的工具调用。用户自行配置的模型使用各自额度。

## 检查

- 打开应用域名和 `/healthz`，核对构建页面及运行状态。
- 使用预设的邮箱和密码登录负责人账号。另用匿名浏览器确认能查看示例活动及已开放的公开活动。
- 需要开放开户时，保存新的密文邀请码，用两个测试账号验证活动、资料与对话隔离。使用同一账号跨设备及重启后恢复工作区。
- 导入虚构资料，执行索引、保存草稿、首次发布和报名，检查重启后记录是否保留。
- 登录后打开模型设置，核对「Agent 对话」与「资料整理」显示的当前模型，分别测试工具调用和证据提取。正式投递前使用测试收件人验证 Resend 与确认链接。
- 使用访客页面和未保存个人配置的账号，确认 Agent 输入框的「自动」可使用平台 MiniMax。保存测试账号的个人模型后，从同一输入框分别指定「我的模型」及「平台 MiniMax」，核对返回模型名称。
- 邮件变量保存后，等待创空间重新部署再测试。发给 Resend 账号绑定邮箱以外的地址时，`HUIXU_MAIL_FROM` 使用已验证的域。负责人在独立测试活动为收件人建立一条已审核报名，预览后只发一封。先核对服务商是否受理和送达，再在未登录的手机浏览器用邮件链接确认出席，最后按原报名凭证核对回写。使用仅发送密钥时，在 Resend 的 Emails 页面核对投递状态。
